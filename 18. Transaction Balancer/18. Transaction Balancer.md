# 18. Transaction Balancer（连续交易凑和为 0）

> **来源**：你的 bug squash docx。网上没找到原帖，题面照抄文档。

## 题目

```
You are given a list of integer transactions representing money flow in and out of an
account. Each transaction can be positive (credit / income) or negative (debit / expense).

Process the transactions sequentially and identify continuous groups of transactions
whose total sum is zero. If during accumulation the running balance ever becomes
negative, that group is considered invalid and should not be continued.
Output all valid zero-sum groups. If no valid groups exist, return an empty result.

Example 1: [2, -2, 3, -1, -2, 4, -4] -> [[2, -2], [3, -1, -2], [4, -4]]
Example 2: [3, -4, 2, 1, -3]         -> [[2, 1, -3]]
           ([3, -4]: the running sum goes negative -> invalid, stop;
            [2, 1, -3] sums to zero -> valid)

Requirements: efficient for large inputs; works for any integer list;
the output format is up to you; write your own unit tests.

Optional follow-ups:
1. How would you handle floating-point transactions (dollars and cents)?
2. How would you modify the logic if the transactions come in real time as a stream?
```

## 思路

一次遍历，O(n) 时间：维护"当前组"和 running balance。
- balance == 0：当前组收成一组，清空
- balance < 0：这组作废，从下一笔重新开始（例 2 里 `-4` 之后从 `2` 开始）
- 结尾没回到 0 的组丢掉

**Follow-up 1（钱）**：不要用 float 加钱。`0.1 + 0.2 - 0.3` 不等于 0，组永远关不上（测试里专门有这一条）。正确做法是把字符串解析成 `Decimal`，再转成整数"分"来算。
**Follow-up 2（流式）**：需要保存的状态只有"当前组 + balance"，写成一个类，每来一笔调用一次 `add(t)`，组一关上就把它返回。

## 开写前要问的

- 单独一笔 0 算不算一组？（我的实现：算）
- `[1, -1, 1, -1]` 是切成两组，还是要尽量长的一组？（我的实现：一回到 0 就切）
