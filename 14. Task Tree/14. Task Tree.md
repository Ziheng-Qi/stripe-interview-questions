# 14. Task Tree（Task 层级树渲染）

> **来源**：PracHub，2026-09，SWE 技术面（OA 之后一小时的 live coding）。地里题库有 3 个变体：Render a Task Hierarchy from Flat Records / Build a Task and Subtask Hierarchy from Unordered Records / Parse and Format a Hierarchical Task CSV，最近一次是 2026-09-29。
> **可信度**：Part 1、Part 2 的字段和连接符来自面经原文；CSV 具体格式、示例数据、Part 3/4 是按 PracHub 列的 follow-up 重建的，面试时以面试官给的为准。

## 题目（重建版）

```
We store tasks as flat CSV records. There are two kinds of records:

  Root task: timestamp,task,task_id,task_name
  Subtask:   timestamp,subtask,parent_id,task_id,task_name

- timestamp is an integer (seconds)
- the 2nd field is the literal word "task" or "subtask"
- parent_id is the task_id of the parent, which may itself be a subtask
- Records are NOT in any particular order: a child may appear before its parent.

Part 1
Parse the records into a structure that maps every task to its direct children,
and find the root tasks. Roots and siblings are ordered by timestamp (ties: input order).

Part 2
Render the hierarchy as text. A root is printed with no connector. A child that is not
the last among its siblings is printed after "├─ ", the last child after "└─ ".
Deeper levels are indented: "│  " under an ancestor that is not a last child,
"   " under one that is.

Example input:
3,subtask,T2,T4,Write spec
1,task,T1,Launch checkout
5,subtask,T1,T3,Build UI
2,subtask,T1,T2,Design API
4,task,T5,Fraud review
6,subtask,T5,T6,Check rules
7,subtask,T6,T7,Notify team

Expected output:
Launch checkout
├─ Design API
│  └─ Write spec
└─ Build UI
Fraud review
└─ Check rules
   └─ Notify team

Part 3 (likely follow-up)
The input is messy. Skip malformed lines (wrong field count, unknown record type,
bad timestamp), keep only the first record of a duplicated task_id, and REPORT
(instead of silently dropping) orphans (parent never appears) and cycles in the
parent links. Return the tree plus the list of problems.

Part 4 (likely follow-up)
Render only the subtree rooted at a given task_id (that task is printed with no connector).
```

## 思路

- **解析和渲染分开写**：`parse_records → build_tree → render_subtree`，后面每个 part 都是在这几个函数上加东西。
- **不能假设父节点先出现**：先把所有记录读进 `task_id → Task`，再统一建 `children`。把所有 task 按 `(timestamp, 行号)` 排一次序，再依次挂到父节点下，每个兄弟列表自然就是有序的。
- **timestamp 先转 int 再比**：字符串比较时 `"10" < "9"`。如果是同格式的 ISO 时间字符串，可以直接比。
- **前缀怎么算**：每一行 = 祖先留下的前缀 + 自己的连接符。往下一层时，自己是最后一个孩子就补 `"   "`，否则补 `"│  "`。这是两件独立的事：连接符只看自己在兄弟里的位置，前缀看祖先。
- **用显式栈做 DFS**：深度超过 1000 层时 Python 递归会爆栈（测试里有一条 2000 层的链）。
- **环**：每个节点只有一个 parent，顺着 parent 往上走，走回当前路径上就说明有环。环上的节点永远挂不到 root 下面，所以从 root 渲染不会死循环；Part 4 如果从环里的节点开始渲染，靠 `seen` 集合防止死循环。
