## 题目（重建版）

```
We want to find records that belong to the same person (or the same merchant).

Input:
  - records: CSV with a header, columns id,name,email,company
  - weights: a weight per field, e.g. {"name": 0.2, "email": 0.5, "company": 0.3}
  - threshold: e.g. 0.5
  - target_id

Two records MATCH if the sum of the weights of the fields on which they are equal
is >= threshold. (Compare case-insensitively after trimming; empty values never match.)

Part 1: Return the ids of all records that directly match the target.
Part 2: Also return records reachable in one more hop
        (if 1 matches 2 and 2 matches 3, return 3 even though 1 does not match 3).
Part 3: Return every record linked to the target through any number of hops.

Example:
id,name,email,company
1,Alice,alice@x.com,Stripe
2,Alicia,alice@x.com,Stripe
3,Alice,al@y.com,Google
4,Bob,bob@z.com,Stripe
5,Alicia,ali@w.com,Stripe
6,Al,ali@w.com,Square

weights: name 0.2, email 0.5, company 0.3; threshold 0.5; target 1
  1-2: email + company = 0.8 -> match
  2-5: name + company  = 0.5 -> match
  5-6: email           = 0.5 -> match
  1-3: name only = 0.2, 1-4: company only = 0.3 -> no match

Part 1 -> [2]
Part 2 -> [2, 5]
Part 3 -> [2, 5, 6]
```

## 思路

- **Part 1**：`match_score` 把相等字段的权重加起来，再和阈值比。
- **Part 2 / 3**：其实是同一个 BFS，区别只是限不限层数。先两两比较建邻接表（n² 次比较，面试规模够用），再从 target 出发做 BFS：`max_hops=1 / 2 / None` 分别对应 Part 1 / 2 / 3。
- **额外**：如果面试官问"把所有记录分组"，用 union-find（代码里的 `all_groups`）。
- **浮点坑**：`0.7 + 0.1 >= 0.8` 在 Python 里是 False。比较时加 `1e-9` 的容差，或者把权重乘 100 变成整数。
- **数据量大时的优化**（口述即可）：按 `(字段, 值)` 建倒排索引，只比较至少共享一个值的记录对。
