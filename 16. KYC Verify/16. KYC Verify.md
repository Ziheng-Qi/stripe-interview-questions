# 16. KYC Verify — Business Account Data Verification（地里题库原题，5 步）

> **来源**：一亩三分地题库。频率 Medium，**最近一次 2026-10-04**，出现在 OA、tech screen 和 phone screen 里。
> 和 13 号 Col Verify 是同一道题的不同版本。最大的区别是：**这一版的禁用词查的是 col5（Full Description），13 号查的是 col2**。另外多了第 5 步：输出错误码。
> 代码：同一文件夹里的 `validate_businesses.py`。下面"变体"一节对应另外两个文件。

## 题目

```
Build a "Know Your Customer" (KYC) system. Read business accounts from a CSV string and decide
whether each one is VERIFIED or NOT VERIFIED. Write validate_businesses(csv_data).

Columns (first line is the header):
  col1 Business ID, col2 Legal Name, col3 Website URL,
  col4 Short Description, col5 Full Description, col6 Product Details

Output, one line per business, in input order:
  VERIFIED: <business_name>
  NOT VERIFIED: <business_name>

Part 1 - Missing info: all 6 fields must have text (a field with only spaces is empty).
         If the name itself is empty, print it blank ("NOT VERIFIED:").
Part 2 - Description length: col5, after stripping, must be 5 to 31 characters (inclusive).
         Checked after Part 1.
Part 3 - Blocked words: col5 must not contain (case-insensitive)
         ONLINE STORE, ECOMMERCE, RETAIL, SHOP, GENERAL MERCHANDISE.   (col6 is ignored)
Part 4 - Name match: split col2, col4, col5 on whitespace, drop "LLC" and "Inc", ignore case.
         At least 50% of the name's words must appear in col4 OR col5.
Part 5 - Error codes: instead of NOT VERIFIED, print the FIRST failing check:
         empty fields      -> ERROR_MISSING_FIELDS
         bad length        -> ERROR_INVALID_LENGTH
         blocked word      -> ERROR_GENERIC_NAME
         name mismatch     -> ERROR_NAME_MISMATCH
```

Part 5 的例子：

```
col1,col2,col3,col4,col5,col6
BIZ001,Pawsome Pets Inc.,pawsomepets.com,Pawsome,PAWSOME PETS INC,Premium pet supplies
BIZ002,Bean Bliss Coffee,beanbliss.com,,,Artisan coffee roasters
BIZ003,Short Name,short.com,Short,SHRT,Products
BIZ004,Generic Store,generic.com,Store,RETAIL,Various items
BIZ005,Mismatched Corp,mismatch.com,Wrong,DIFFERENT BUSINESS,Services

VERIFIED: Pawsome Pets Inc.
ERROR_MISSING_FIELDS: Bean Bliss Coffee
ERROR_INVALID_LENGTH: Short Name
ERROR_GENERIC_NAME: Generic Store
ERROR_NAME_MISMATCH: Mismatched Corp
```

另外 4 个 part 的完整例子都写在代码的测试里。

## 思路

- **每条规则写成一个 `check_xxx(fields)`**：通过返回 `None`，不通过返回错误码，按顺序放进 `CHECKS` 列表。Part k 就跑前 k 个检查。Part 5 的逻辑完全不用改，只是把打印的 `NOT VERIFIED` 换成错误码。前面写好的测试都还能过，面试官很看重这一点。
- **遇到第一个错误就停**：用惰性的生成器，或者 for 循环里 `break`。这样少列的行不会跑到后面的检查里，也就不会出现 `fields[4]` 越界。
- **名字匹配用 set**：`2 * len(name & (short | full)) >= len(name)`，用整数比较，不用除法。名字去掉 LLC / Inc 之后如果是空的，按不匹配处理。
- **禁用词用子串匹配**（和参考答案一致），所以 "WORKSHOP" 也会命中 "SHOP"。这一点一定要问。

## 开写前要问的

- CSV 一定格式正确吗？某一行列数不够怎么办？
- 名字为空时打印什么？`NOT VERIFIED:` 后面要不要留空格？
- 禁用词是子串匹配还是整词匹配（WORKSHOP / SHOP）？
- 名字里的标点怎么处理？比如 "Inc." 算不算 Inc，"Ben & Jerry's" 怎么切词？我的代码会去掉词尾的 `.` 和 `,`。
- col4 和 col5 能合在一起比吗？名字里重复的词算一次还是多次？

## 变体（同一题型的其他报告）

**PracHub 2026-08 技术面版**（`kyc_verify.py`）：
- 字段是 business_name / url / nickname / description。
- 没有名字的行直接跳过、不输出。
- **长度限制 5–32，检查的是 nickname，空格也算长度**。
- 禁用词查 description。
- 名字至少一半的词要出现在 nickname 里；只去掉名字**结尾**的 LLC / Inc。

**商户信息解析（2026-06 Backend 一面）**（`merchant_parsing.py`）：
1. 解析 `key:value` 格式的字符串。
2. 过滤掉有空值或 null 的商户。
3. 把 description 和一组预设值做匹配。
