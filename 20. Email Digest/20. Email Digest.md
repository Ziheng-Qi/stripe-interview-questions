## 题目

```
You are building an email notification system. Users can subscribe to topics and set
preferences for how often they want to receive emails (immediately, daily digest, or
weekly digest). You receive a stream of events and must determine which emails to send
and when.

Part 1: Parse a list of subscriptions in the format user_id,topic,frequency.
        Output all active subscriptions grouped by user.
Part 2: Given a stream of events (timestamp, topic, content), for users subscribed to a
        topic with immediate frequency, output an email to that user right away.
Part 3: For users with daily frequency, batch all events from the same day and send one
        digest email at the end of the day. For weekly, batch by week.
Part 4: Users can unsubscribe at any time. An unsubscribe event (timestamp, user_id, topic)
        means the user should receive no further emails for that topic, including any
        pending digests that haven't been sent yet.
```

示例（timestamp 单位是秒，1 天 = 86400）：

```
subscriptions:
alice,payments,immediate
alice,fraud,daily
bob,payments,daily
bob,fraud,weekly

events:
publish      100    payments  p1
publish      200    fraud     f1
unsubscribe  300    alice     fraud
publish      400    fraud     f2
publish      86450  payments  p2

output:
100 -> alice [immediate] payments: p1
86400 -> bob [daily digest] payments: p1
86450 -> alice [immediate] payments: p2
172800 -> bob [daily digest] payments: p2
604800 -> bob [weekly digest] fraud: f1; fraud: f2
(alice's pending daily digest containing f1 is dropped by her unsubscribe)
```

## 思路

- 订阅关系反过来存成 `topic -> {user: frequency}`，发布时直接找到订阅者。
- 待发的 digest 按 `(user, frequency, 第几天 / 第几周)` 攒着，其中 `第几天 = ts // 86400`。
- 处理每个事件之前，先把"周期已经结束"的 digest 发出去（`_flush_until(ts)`）；全部事件处理完后，`finish()` 把剩下的都发掉。
- 退订：删掉订阅，再把这个用户待发 digest 里该 topic 的内容删掉；删空了就不发。
- 事件先按 timestamp 排序，同一时间的保持输入顺序。

## 开写前要问的

- digest 的时间戳记成什么：周期结束的那一刻，还是下一个事件到来的时候？
- 一周从哪天开始算？用什么时区？
- 同一个用户的 daily digest 是所有 topic 合成一封，还是每个 topic 一封？（我的实现：合成一封）
- 事件流结束时还没到周期末的 digest 要不要发？（我的实现：发）
- 同一时刻既有发布又有退订，先处理哪个？
