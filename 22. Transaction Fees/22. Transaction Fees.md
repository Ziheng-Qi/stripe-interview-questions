## 样例我算出来的结果

**Part 2**：fee = amount × 费率 + 30

| | 计算 | 精确值 | 向下取整 | 四舍五入 |
|---|---|---|---|---|
| py_1 | 1000 × 2.1% + 30 | 51 | 51 | 51 |
| py_2 | 2500 × 2.3% + 30 | 87.5 | 87 | 88 |
| py_3 | 3400 × 2.4% + 30 | 111.6 | 111 | 112 |
| py_4 | 3400 × 2.5% + 30 | 115 | 115 | 115 |

py_2、py_3 算出来不是整数，所以**一定要问清楚怎么取整**，或者直接看 Sample Output。

**Part 3**：交易量按 (merchant, provider, country) 分别累计。**py_1 正好是 10000，明显是在测边界**：

| | 严格大于 ">"（surpasses 的字面意思，代码默认） | 大于等于 ">="（达到就算） |
|---|---|---|
| py_1 | 之前累计 0 → 2.1% → 240 | 240 |
| py_2 | 之前累计 10000，没有"超过" → 2.1% → 82.5 | 已经达到 → 2.0% → 80 |
| py_3 | DE 单独累计，之前 0 → 2.3% → 260 | 260 |
| py_4 | 之前累计 10000 → 2.3% → 87.5 | 2.1% → 82.5 |
| py_9 | acct_2 单独累计 → 2.1% → 135 | 135 |

还有第三种理解：把累计推过 10000 的那一笔自己就用低费率。在这个样例上，它的结果和 ">=" 一样。用 ">=" 只需要在代码里改成 `inclusive=True`。

## 思路

- **费率表写成数据**：表里 "DE, FR, AT" 是一行，代码里展开成 `(provider, country) → rate` 的 dict。国家代码统一转小写，因为输入是 "ie"，表里是 "IE"。
- **钱用 Decimal 算**：`Decimal(amount) * Decimal("2.4") / 100` 是精确的；用 float 的话，`3400 * 0.024` 会得到 `81.60000000000001`。最后再按题目要求取整。
- **Part 2 只改"查费率"这一步**：fixed fee 和 dispute fee 都不变。表里没有的 provider / country 组合，退回 Part 1 的统一费率（这一点要问）。
- **Part 3 要维护状态**：`volume[(merchant, provider, country)]`，按输入顺序处理（"irrespective of the date" 指不按天清零）。先用"这一笔之前的累计"决定这一笔的费率，再把这一笔加进累计。只有 completed 的 payment 才计入交易量（这一点也要问）。
- **表头有空格**：Part 3 样例的表头是 `payment_provider, status`，status 前面多了一个空格，DictReader 读出来的 key 会是 `" status"`，所以 key 也要 strip。
