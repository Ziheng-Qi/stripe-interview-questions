# 19. Fraud Rules（4 part 逐行校验 + 错误码）

> **来源**：LeetCode Discuss "Stripe phone screen 4 part interview experience"（没写日期和岗位）。
> **可信度**：四个 part 的要求来自原帖；字段名、阈值、黑名单、用户画像、错误码名称都是重建的。
> 和 8 号 Fraud Reporting 不是同一道题，结构反而跟 13 号 / 16 号一样，是"逐行跑一串校验"。地里 2026 年那篇 fraud 技术面正文锁着，不确定考的是哪个版本，两个都练一下。

## 题目（重建版）

```
Transactions arrive as CSV with six fields:
transaction_id,user_id,amount,payment_method,country,timestamp

Part 1 - Data integrity: all six fields must be non-empty (and parseable).
         Print "<transaction_id> OK" or "<transaction_id> INVALID".
Part 2 - High-risk rules: flag SUSPICIOUS if the amount is outside the normal range
         (e.g. 1.00-10000.00) or the payment method is on a blocked list
         (e.g. prepaid_card, crypto).
Part 3 - User behavior: compare the transaction with the user's history (usual countries,
         typical hours, usual amount range). At least 50% of these attributes must match,
         otherwise SUSPICIOUS. Users with no history skip this check.
Part 4 - Error reporting: instead of SUSPICIOUS, print up to two specific error codes
         ordered by priority, or "OK" if there is no issue. Keep the report's columns aligned.

Example:
t1,u1,25.00,card,US,2024-05-01T10:15:00
t2,u1,,card,US,2024-05-01T11:00:00
t3,u2,50000.00,card,US,2024-05-01T12:00:00
t4,u2,30.00,prepaid_card,US,2024-05-01T12:30:00
t5,u1,40.00,card,BR,2024-05-01T03:00:00
t6,u3,15.00,card,FR,2024-05-01T09:00:00
t7,u2,20000.00,crypto,RU,2024-05-01T02:00:00

history: u1 = {US, CA}, 08-22h, 10-100;   u2 = {US}, 09-18h, 20-200

Part 4 output:
TXN  USER  RESULT
t1   u1    OK
t2   u1    E01_INVALID_FIELD
t3   u2    E03_AMOUNT_OUT_OF_RANGE
t4   u2    E02_BLOCKED_METHOD
t5   u1    E04_BEHAVIOR_MISMATCH
t6   u3    OK
t7   u2    E02_BLOCKED_METHOD E03_AMOUNT_OUT_OF_RANGE
```

## 思路

- `find_issues(txn, part)` 返回这一行的所有问题码，按优先级排好序。Part 1–3 再把它映射成 OK / INVALID / SUSPICIOUS，Part 4 直接取前两个码。
- 金额用 `Decimal` 解析，不要用 float；解析失败也算 E01。
- "至少 50%"用整数比较：`2 * matched >= total`。
- 时间段可能跨午夜（比如 22 点到 2 点），`in_hours` 处理了这种情况。
- 列对齐：先算出每列的最大宽度，再用 `ljust` 补齐；最后一列 `rstrip`，避免行尾多出空格。
