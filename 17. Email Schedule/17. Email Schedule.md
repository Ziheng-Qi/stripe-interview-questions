# 17. Email Schedule（邮件调度的三种变体）

这几种和 11 号 Email 是同一类题，做法都是**先把"规则"展开成"绝对时间 + 邮件"，再按题目要求排序，或者按当前时间过滤**。区别全在细节里，读题时要看清三件事：offset 相对的是什么、单位是什么、要的是整条时间线还是只要"现在"该发的。

## 变体 A：send_schedule map，只返回"现在"要发的

> **来源**：你的 bug squash docx。网上没找到原帖，但下面的变体 C 是 PracHub 上同类的技术面题。

```
You are given a list of users and an email send schedule. Each user has a start time
and an end time.

send_schedule is a map:
- The keys "start" and "end" are fixed events at the user's start and end times.
- Any other key is a numeric string: an offset in MINUTES relative to the user's START.
  "-15" means 15 minutes before start, "60" means 60 minutes after start.
- Each key maps to the type of email to send.

Given users, send_schedule and the current timestamp, return which users should receive
which emails at the current time. Do not hardcode any offsets: new numeric keys may be
added in the future.

users = [{"name": "A", "start": 100, "end": 400}, {"name": "B", "start": 115, "end": 300}]
send_schedule = {"start": "Welcome", "-15": "Starting soon",
                 "60": "How is it going?", "end": "Goodbye"}

now = 100 -> [("A", "Welcome"), ("B", "Starting soon")]
now = 175 -> [("B", "How is it going?")]
now = 300 -> [("B", "Goodbye")]
```

可能的追问：输出所有用户的完整时间线，按时间排序——对应代码里的 `full_timeline`。

## 变体 B：发票提醒邮件，按时间顺序输出标题

> **来源**：Glassdoor，45 分钟技术面。下面第一段是原文，输入格式是重建的。

```
For this question, you will be outputting the subject line of each email we send for
customers' invoices in sorted order. (Use any library/tool for sorting.)

Your invoicing system will need to be able to configure a reminder schedule. For example,
you might want to send one email 10 days before the invoice comes out, one email when the
invoice comes out, one email 20 days after the invoice comes out, and one email when the
invoice is due, which is 30 days from when the invoice first came out.

invoices = [
  {"invoice_id": "inv_1", "customer": "acme",   "invoice_date": "2024-03-15"},
  {"invoice_id": "inv_2", "customer": "globex", "invoice_date": "2024-03-08"},
]
schedule = [
  {"offset": -10,   "subject": "Upcoming invoice"},
  {"offset": 0,     "subject": "New invoice"},
  {"offset": 20,    "subject": "Payment reminder"},
  {"offset": "due", "subject": "Invoice due"},
]

Output:
2024-02-27 [Upcoming invoice] Invoice inv_2 for globex
2024-03-05 [Upcoming invoice] Invoice inv_1 for acme
2024-03-08 [New invoice] Invoice inv_2 for globex
2024-03-15 [New invoice] Invoice inv_1 for acme
2024-03-28 [Payment reminder] Invoice inv_2 for globex
2024-04-04 [Payment reminder] Invoice inv_1 for acme
2024-04-07 [Invoice due] Invoice inv_2 for globex
2024-04-14 [Invoice due] Invoice inv_1 for acme
```

注意：日期用 `datetime.date` + `timedelta` 算，别自己手动加天数（会出跨月、闰年的错）。可能的追问：发票提前付清后就不再发提醒；不同客户用不同的提醒计划。

## 变体 C：账户通知规则，只输出"今天"的

> **来源**：PracHub，Generate Account Email Notifications（Technical Screen，页面更新于 2026-05）。

```
Input: current_day; accounts with account_id, created_day, expires_day;
rules with name, trigger, template (plus offset_days for days_before_expiration).

Triggers:
  on_create               -> created_day == current_day
  days_before_expiration  -> expires_day - current_day == offset_days
  after_expiration        -> current_day > expires_day   (every day after expiry, not once)

Return only the notifications due on current_day, as "<account_id> <rule_name> <template>".
Accounts in input order; for each account, matching rules in configuration order.
Up to 200,000 accounts and 200,000 rules.
```

注意：20 万 × 20 万不能写两层循环。先把规则按 trigger 分桶，`days_before_expiration` 再按 `offset_days` 建 dict；每个账户只查和自己相关的几个桶，最后按规则的原始下标排序输出。

## 几种变体对比

| | offset 相对什么 | 单位 | 输出什么 |
|---|---|---|---|
| A | start | 分钟 | 现在要发的 |
| B | 发票日期；"due" = 发票日 + 30 天 | 天 | 全部，按时间排序 |
| C | 到期日 | 天 | 今天要发的 |
| 11 号 | 开始日 / 到期日（到期前 15 天） | 天 | 全部按时间排序（还有改 plan、续期） |
